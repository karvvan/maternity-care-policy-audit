## PPT 작업 규칙 ★

**`04_제출물`의 PPT 두 개는 사람이 PowerPoint로 직접 편집하는 파일이다. 이것이 원본이다.**
생성 스크립트를 돌려 통째로 덮어쓰면 그 편집이 전부 사라진다. 그래서 규칙은 세 가지다.

1. **생성기는 `05_작업자료/_PPT생성본/`에만 쓴다.** 제출본에 직접 쓰지 않는다.
2. **수정은 제출본을 읽어 필요한 부분만 얹는다** — `03_분석/_문서생성/PPT_패치.py` 사용.
3. **반영은 사용자가 요청할 때만**, 그리고 파일이 닫혀 있을 때만 한다(`deploy()`가 잠금을 확인하고
   직전 상태를 백업한다).
4. **한 파일을 동시에 열지 않는다.** PowerPoint는 파일 전체를 메모리에 들고 있다가 저장할 때
   통째로 덮어쓴다. "사용자가 연 뒤 → 스크립트가 디스크를 수정 → 사용자가 저장"이 되면 스크립트의
   수정이 사라진다. 잠금(`~$`) 검사만으로는 이 순서를 막지 못한다.
5. 그래서 수정 내역을 `PPT_정합성점검.py`에 선언적으로 남긴다. 언제든 돌려서 빠진 항목을
   확인하고 복구할 수 있다(멱등이라 몇 번을 돌려도 안전).

```bash
python 03_분석/_문서생성/PPT_정합성점검.py           # 점검만
python 03_분석/_문서생성/PPT_정합성점검.py --apply   # 빠진 항목 복구
```

### 반영 보류 (다른 사람이 편집 중인 덱)

두 사람이 같은 pptx를 동시에 만지면 나중에 저장한 쪽이 상대 작업을 덮어쓴다.
그래서 남이 잡고 있는 덱은 `PPT_패치.py`의 `HOLD` 에 적어 **쓰기를 막는다**
(읽기·점검은 계속 된다). 넘겨받으면 그 줄을 지운다.

```python
HOLD = {'결과': '팀원이 작업 중 (2026-08-12~). 대표자가 다시 넘겨줄 때까지 반영 금지'}
```

`PowerPoint.Application` COM은 쓰지 않는다 — 실행 중인 인스턴스에 붙기 때문에
`Quit()`이 사용자가 편집 중인 창까지 닫아 버린다.

```python
# 수정 예: 제출본 위에 문구 하나만 고쳐 staging에 저장
from PPT_패치 import load, replace_text, save, is_open, deploy
prs = load('결과')
replace_text(prs, '옛 문구', '새 문구')
save(prs, '결과')            # → 05_작업자료/_PPT생성본/
# deploy('결과')             # 사용자가 반영하라고 할 때만
```

### 그림·덱 재생성 (staging 출력)

```bash
python 03_분석/_문서생성/그림_지도_생성.py          # 컬러판 → 04_제출물/그림 (보고서 PDF용)
FIG_MONO=1 python 03_분석/_문서생성/그림_지도_생성.py  # 무채색판 → 04_제출물/그림_모노 (PPT용)
python 03_분석/_문서생성/결과PPT_생성.py            # 20장 → staging
python 03_분석/_문서생성/계획서PPT_생성.py          # 13장 → staging
```

PPT는 무채색 테마다. 색은 쓰지 않고 명도 차이로만 위계를 만들며, 표지 오른쪽은
이미지·삽화를 직접 넣을 수 있도록 비워 둔다.

시연영상 생성기는 쓰지 않는다(`99_아카이브/생성기_기각/`에 보관).
