## 2. 네이버 데이터 — 광고주센터를 꼭 써야 하나?

### 결론: **필수 아님. 데이터랩이 우선이고, 광고 API는 선택적 보강.**

두 경로의 성격이 완전히 다르다.

| | **네이버 데이터랩** | **네이버 검색광고 API (광고주센터)** |
|---|---|---|
| 제공 값 | **상대 지수** (기간 내 최댓값=100) | **월간 절대 검색수** (PC/모바일 분리) |
| 시계열 | ✅ **있음** (일·주·월 단위 장기) | ❌ 없음 (최근 시점 스냅샷) |
| 지역 분해 | 제한적 | ❌ 없음 |
| 계정 | 네이버 개발자센터 앱 등록 | 네이버 검색광고 계정 → 광고시스템 > 도구 > **API 사용관리**에서 신청 |
| 비용 | 무료 | **무료** (API 라이선스 무료) |
| 부가 정보 | 성별·연령·기기별 | 월평균클릭수, **경쟁정도**, 월평균노출광고수 |

### D안에서의 판단

**❌ 광고 API를 주력으로 쓰면 안 되는 이유**
- **지역별 분해가 안 된다.** 상권 단위 피처로 쓸 수 없다 — D안의 예측 단위가 (상권 × 업종)인데 상권 축이 없다
- 시계열이 없어 "성장 업종 / 쇠퇴 업종"을 판별할 수 없다

**✅ 데이터랩이 우선인 이유**
- 시계열이 있으므로 **업종별 검색 트렌드의 기울기**를 뽑아 **"성장/쇠퇴 업종 지표"** 를 만들 수 있다
- 이건 **동일 키워드 내 시계열 비교**라서 상대 지수여도 방법론적으로 타당하다
  (키워드 *간* 비교가 불가능한 것이지, 같은 키워드의 시간 변화는 정확히 이 데이터가 답할 수 있는 질문이다)

**✅ 그래도 광고 API를 넣으면 좋은 이유 — 두 축 조합**

```
데이터랩      → 추세 (이 업종의 수요가 늘고 있는가)
검색광고 API  → 규모 (이 업종의 절대 수요가 큰가)
             ↓
     "성장 중 + 규모 큼"  = 유망 업종
     "성장 중 + 규모 작음" = 틈새 업종
     "정체 + 규모 큼"     = 포화 업종
```

이 2×2 분류는 그 자체로 보고서에 실을 만한 인사이트다.
그리고 **데이터 출처가 하나 늘어나는 것은 평가기준 항목②(30점)에서 직접 이득**이다.

**→ 권고: Tier 5로 두되 넣는다. 단 8/8 이후 여유가 있을 때. 없어도 D안은 성립한다.**

> 팀원이 원래 검색 데이터 아이디어를 냈으므로, **이 파트를 팀원에게 맡기면 기여감이 유지된다.**

## 4. ⚠️ D안 최대 난관 — 업종 코드 체계 정합화

데이터마다 업종 분류 체계가 **전부 다르다.**

```
서울시 상권분석    →  100개 서비스업종 코드 (한식음식점, 커피-음료, …)
인허가 데이터      →  업태구분명 (한식, 중식, 경양식, 호프/통닭, 김밥(도시락), …)
공정위 가맹정보    →  가맹 업종 분류 (치킨, 피자, 커피, …)
네이버 검색        →  자연어 키워드
```

**이 4개를 잇는 매핑 테이블을 직접 만들어야 한다.** D안에서 가장 손이 많이 가는 작업이다.

> **그런데 이게 평가기준 항목②(30점)의 핵심 득점 지점이다.**
> *"분석계획에 맞는 데이터를 수집하였는가 / 데이터 전처리 과정은 적정하게 수행되었는가"*
>
> 매핑 테이블 작성 과정과 판단 근거를 보고서에 명시하면 그대로 점수가 된다.
> 귀찮은 작업이 아니라 **배점이 걸린 작업**으로 대해야 한다.

**작업 요령**
- 전 업종을 매핑하려 하지 말 것. **음식점 업태 10~15개 정도로 시작**
- 애매한 건 제외하고 사유를 기록 (제외 사유도 보고서 내용)
- 매핑 테이블은 CSV로 관리하고 소스와 함께 제출

## 5. 데이터 다양성이 왜 점수인가 — 평가기준 대조

| 평가지표 (항목② · 30점) | 이 로드맵의 대응 |
|---|---|
| "분석계획에 맞는 데이터를 수집하였는가" | **5개 이상 독립 출처** — 인허가(행안부) / 상권(서울시) / 가맹(공정위) / 생활인구(서울시·KT) / 부동산(부동산원) / 검색(네이버) |
| "데이터 전처리 과정은 적정하게 수행되었는가" | 좌표계 변환(EPSG:5174→WGS84), 업종코드 정합화, 공간 조인, 폐업일자 결측·이상치 처리 |
| "탐색적데이터분석(EDA)이 의미있게 진행되었는가" | 업종별 생존곡선, 상권별 매출 분포, 시간대별 인구 프로파일, 집적도-매출 산점도 |

> **사용자 직감이 배점상 정확하다 — 출처가 다양할수록 유리하다.**
> 다만 다양성을 위한 다양성은 안 된다. 각 데이터가 **어떤 피처를 만들기 위해 필요한지**를
> 계획서에 한 줄씩 명시해야 항목①(30점, "분석계획이 적정하게 수립되었는가")까지 함께 먹는다.

## 6. 업데이트된 D안 차별화 — 이제 4종

| # | 차별화 | 근거 데이터 |
|---|---|---|
| ① | 업종별 **집적계수** 추정 (포화 vs 집적) | 점포-상권 `유사_업종_점포_수` |
| ② | **상권 임베딩** 기반 협업 필터링 | 추정매출-상권 행렬 |
| ③ | **반사실 비교** (지역 고정 / 업종 고정) | 모형 출력 |
| ④ | **시간대 궁합 매칭** ★신규 | 서울시 생활인구 (시간대별) |
| ⑤ | **생존분석** ★신규 — Kaplan-Meier / Cox | 인허가 데이터 (개업일·폐업일) |

> ⑤가 추가되면서 D안의 성격이 달라졌다.
> 이전에는 "집계 데이터로 셀 단위 추정"이 한계였으나,
> 이제 **개별 사업장 생존기간이라는 진짜 라벨**을 갖게 된다.
> 출력 표현도 **"동종 업종 대비 생존 기간 백분위"** 처럼 훨씬 강해진다.
