## 1. 이대로 가면 무너지는 지점 2개

### 위험 ① 부문 미스매치 — "이건 분석이 아니라 서비스 개발 아닌가"

공고문 정의를 다시 보면:

- **빅데이터 분석**: *"예측 모형 개발, 인사이트 탐색, 정책제안"*
- **AI응용**: *"LLM 등의 AI기술을 이용하여 도메인의 문제 해결... **단 빅데이터 분석이 중심 주제가 아니어야 함**"*

"LLM에게 말하면 추천해준다"는 서술은 무게중심이 **AI응용/SW개발** 쪽에 있다.
빅데이터 분석 부문으로 제출하면 서류심사에서 부문 정합성을 의심받을 수 있다.

> **해결: 무게중심을 뒤집는다.**
> LLM이 추천하는 게 아니라, **통계·ML 모형이 추천하고 LLM은 입력 해석과 결과 설명만** 담당한다.
> LLM은 두뇌가 아니라 **인터페이스**다.

이 설계는 세 가지를 동시에 얻는다.
1. 부문 정합성 확보 — 심장이 예측 모형이다
2. 시연 임팩트 유지 — 대화형 UI는 그대로
3. **환각 위험 제거** — LLM이 숫자를 만들지 않으므로 틀린 수치가 나올 수 없다

**설계 원칙으로 못 박을 것**

> ### 🔒 LLM은 숫자를 생성하지 않는다. 모형이 낸 숫자를 설명할 뿐이다.

이 원칙을 보고서에 명시하면 그 자체로 신뢰성 가점 요인이 된다.
(발표심사에서 "LLM이 지어낸 거 아니냐"는 질문이 반드시 나온다. 이 원칙이 그 답이다.)

### 위험 ② "성공확률"은 이 데이터로 계산할 수 없다

서울시 상권분석 데이터는 **(상권 × 업종 × 기간) 집계 데이터**다. **개별 점포 ID가 없다.**
따라서 "당신의 가게가 3년 뒤 살아있을 확률 73%"는 **근거를 댈 수 없는 숫자**다.

이걸 그대로 출력하면 발표심사에서 "그 73%는 어떻게 나온 겁니까"라는 질문 하나에 무너진다.

> **해결: 예측 단위를 셀(cell)로 정의하고, 출력을 분포 내 위치로 표현한다.**

| 잘못된 설계 | 확정 설계 |
|---|---|
| 예측 단위 = 개별 점포 | 예측 단위 = **(상권 × 업종) 조합** |
| 출력 = "성공확률 73%" | 출력 = **"이 조합의 폐업률은 서울시 동일 업종 상권 중 하위 15%"** |
| 근거 없음 | 집계 데이터로 직접 계산 가능 |

이건 단순히 정직한 게 아니라 **통계적으로 더 성숙한 표현**이라 심사에서 오히려 유리하다.

## 2. 차별화 3종 — 이게 없으면 흔한 출품작이 된다

솔직히: **"상권 데이터 + 창업 추천"은 국내 데이터 공모전 최다 빈출 주제**다.
여기에 LLM을 붙이는 것도 최근 흔한 구성이다. 아래 3가지를 반드시 넣어야 차별화된다.

### 차별화 ① 포화인가 집적인가 — 업종별 집적계수 추정 ★가장 강력

같은 업종 점포가 주변에 많으면 **경쟁(포화)** 인가, 손님을 끌어모으는 **집적효과** 인가?

**답은 업종마다 다르다.**
- 카페·음식점 → 몰려 있을수록 유리 (집적 이익: "거기 가면 뭐라도 있다")
- 세탁소·미용실 등 근린 서비스 → 몰려 있으면 불리 (순수 경쟁)

점포 테이블에 **`유사_업종_점포_수`** 컬럼이 있으므로, 업종별로 이 관계를 실증 추정할 수 있다.

> **100개 업종 각각의 "집적계수"를 추정하는 것 자체가 독립된 분석 성과이자 인사이트다.**
> 그리고 이게 추천 모형의 핵심 피처가 된다.

이 하나만으로 "그냥 XGBoost 돌려서 점수 매긴 출품작"과 완전히 구분된다.

### 차별화 ② 상권 임베딩 기반 협업 필터링 — 진짜 "추천시스템"

(상권 × 업종) 매출 행렬에 **행렬분해(NMF 또는 Truncated SVD)** 를 적용해
상권 임베딩과 업종 임베딩을 얻는다.

```
매출행렬 R (1,500 상권 × 100 업종)  ≈  W (1,500 × k)  ×  H (k × 100)
                                       상권 임베딩      업종 임베딩
```

이렇게 하면:
- **"내 상권과 유사한 상권들에서 잘 되는 업종"** 추천이 가능 (넷플릭스식 협업 필터링)
- 데이터가 희소한 조합(신규 상권, 소수 업종)도 잠재 요인으로 추론 가능
- 상권 임베딩을 2차원으로 축소해 **"서울 상권 지도"** 시각화 → 영상용 그림이 나온다

대부분의 출품작은 지도교사 학습 점수를 정렬할 뿐이다. 이건 방법론이 다르다.

### 차별화 ③ 반사실적 비교 (counterfactual)

사용자 입력을 **평가만 하지 않고, 두 축으로 대안을 제시**한다.

```
사용자 입력: "홍대에서 카페"
   ↓
① 업종 고정 → 지역을 바꾼다: "카페를 한다면 홍대보다 A상권"
② 지역 고정 → 업종을 바꾼다: "홍대를 고수한다면 카페보다 B업종"
③ 나란히 비교: 당신의 선택 vs 최적 대안
```

사용자가 원했던 *"어느 지역에서 하는 게 좋고, 어떤 업종이 좋고"* 에 정확히 대응하는 구조다.

## 3. 입력(Input) 설계 — 확정

### Layer 1 · 사용자에게 묻는 것 — **딱 3개만**

```
"강남 근처에서 2억 정도로 카페 하려는데 어디가 좋을까?"
```
↓ **LLM이 구조화 JSON으로 파싱**
```json
{
  "업종":     "커피-음료",
  "희망지역": { "유형": "자치구", "값": ["강남구", "서초구"] },
  "예산":     { "초기자본": 200000000 },
  "운영형태": "단독"
}
```

| 항목 | 필수 | 설명 |
|---|---|---|
| 업종 | ✅ | 자연어 → **100개 서비스업종 코드로 매핑** (LLM의 실질적 기여 지점) |
| 희망지역 | ⬜ | 자치구/행정동 또는 `null`(= 서울 전체에서 추천) |
| 예산 | ⬜ | 임대료 제약 필터에 사용 |
| 운영형태 | ⬜ | 단독 / 프랜차이즈 |

> **LLM의 역할이 실제로 유용한 이유**: 사용자는 "카페"라고 말하지 "커피-음료"라고 말하지 않는다.
> 100개 업종 코드로의 매핑, 그리고 누락 항목 되묻기 — 여기서 LLM이 진짜 값을 한다.

### Layer 2 · 시스템이 데이터에서 자동 조달 (사용자는 입력하지 않음)

유동인구, 상주인구, 직장인구, 소득·소비, 집객시설, 아파트, 기존 점포 수,
유사업종 점포 수, 프랜차이즈 비율, 상권변화지표 등급, 임대시세 — **전부**

> **설계 원칙: 사용자에게 최소한만 묻는다.**
> 입력 항목이 많으면 시연이 지루해지고 결측 처리 부담만 커진다.
> "3개만 물어보는데 이만큼 나온다"가 시연에서 훨씬 강하다.

  → **팀원 원안이 여기서 살아난다.** 단 보조 피처로만 사용

### 상권변화지표 4등급 (그대로 쓸 수 있는 라벨)

| 등급 | 의미 | 서울시 공식 해석 |
|---|---|---|
| **LL** | 생존·폐업 평균영업기간 모두 낮음 | 도시재생·신규 개발 상권, 진출입 시 세심한 주의 필요 |
| **LH** | 생존 낮음 / 폐업 높음 | **신규 업체가 경쟁력을 가지는 상권** ← 창업 추천에 유리 |
| **HL** | 생존 높음 / 폐업 낮음 | 기존 업체가 경쟁력을 가지는 상권 |
| **HH** | 둘 다 높음 | 진출입 시 세심한 주의 필요 |

> **LH 등급이 "신규 창업자에게 유리한 상권"이라는 서울시 공식 해석**이 존재한다.
> 이건 우리 추천 결과를 검증할 수 있는 외부 기준이 된다. 놓치면 안 되는 자산.

## 6. 데이터 규모 — 서울로 충분한가

```
상권 약 1,500개 × 업종 100개 × 시점(2021~2025)
  → 이론상 수십만 ~ 300만 셀
  → 희소 조합 제거 후 실사용 수십만 행
```

| 판단 | 결론 |
|---|---|
| "빅데이터"라 부를 규모인가 | ✅ 충분. 10종 테이블 결합 전처리 난이도도 확보 |
| 노트북에서 처리 가능한가 | ✅ pandas 처리 상한선 안쪽 |

## 7. 🚨 반드시 먼저 검증할 리스크 2개 (7/30)

### R1. 공간 단위 변경 — 시계열이 끊길 수 있음

서울시 공지 원문:
> *"2024년부터 서울시 상권분석서비스의 공간 단위가 표준단위구역으로 변경되었습니다.
> 표준단위구역 기준 매출액 데이터는 카드사에서 2021년부터 제공하고 있어
> 데이터의 일관성 및 정확성 확보를 위해 2026년 7월 3일부터 2021년 이후 자료만 제공합니다."*

**해석**: "일관성 확보를 위해"라는 문구로 보아 2021~2025년이 **동일한 표준단위구역 기준으로 재산출**되었을 가능성이 높다. 이게 사실이면 시계열 연결에 문제가 없다.

**하지만 반드시 실물로 확인할 것**: 2021년 파일과 2025년 파일의 **상권 코드 집합이 실제로 일치하는지**.
불일치하면 시계열 학습 설계 자체를 바꿔야 한다.

### R2. 분기 데이터인가 연간 데이터인가

데이터셋 페이지의 갱신주기가 **"연간"** 으로 표기되어 있다.

- 파일 내부에 `기준_년분기_코드` 컬럼이 있으면 → **분기 데이터. 2021~2025 = 약 20시점.** 시계열 예측 가능 ✅
- 연간 집계뿐이면 → **5시점.** 시계열 예측이 사실상 불가 → **설계 변경 필요**
  (이 경우 시점 간 예측을 포기하고, 횡단면 매칭·추천 중심으로 재설계)

> **이 두 가지는 7/30에 파일을 실제로 열어보면 10분 안에 판명된다. 반드시 먼저 할 것.**

## 9. A안(의료 사각지대)과의 비교 — 솔직한 평가

| 기준 | A안 (의료취약지 제도) | D안 (창업 추천) |
|---|---|---|
| **창의성** | **상** (제도 자체를 분석) | 중 (흔한 주제 · 차별화 3종으로 보완 필요) |
| **부문 정합성** | **상** | 중 (구조 뒤집기로 보완) |
| **정책 제안** | **상** (고시 개정 제안) | 중 (서울시 소상공인 정책) |
| **완주 확실성** | 중 (범위 축소 필수) | **상** |
| **시연 임팩트** | 상 (지도) | **상** (대화형 UI + 지도) |
| **데이터 확보 위험** | 중 (좌표·지오코딩 불확실) | **하** (단일 출처 · 즉시 다운로드) |
| **팀 부담** | 상 (공간분석 학습 필요) | 중 |

**선택 기준**
- **창의성과 정책 제안**을 최우선 → **A안**
- **완주 확실성과 시연 임팩트**를 최우선 → **D안** (차별화 3종 필수)

> D안은 "안전하지만 평범해질 위험"이 있고, A안은 "뛰어나지만 못 끝낼 위험"이 있다.
> 2인 팀 · 17일 조건에서는 **D안 + 차별화 3종**이 기대값이 더 높다고 본다.
